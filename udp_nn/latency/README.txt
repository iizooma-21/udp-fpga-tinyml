================================================================
  END-TO-END LATENCY ESTIMATION  —  MLPerf Tiny / UDP Array
================================================================

PURPOSE
-------
Estimates inference latency for each MLPerf Tiny benchmark on:
  - base 12x12 array  (144 PEs)
  - opt_a 12x8 array  ( 96 PEs)
  - opt_b  9x8 array  ( 72 PEs)

Latency model:
  real_cycles = Timeloop_cycles / 6          (UDP: 6 MACs/PE/cycle)
  latency_us  = real_cycles / 200e6 * 1e6    (assuming 200 MHz clock)

FOLDER STRUCTURE
----------------
  latency/
  |-- run_latency.sh        Main WSL runner (runs Timeloop + generates report)
  |-- compute_latency.py    Reads all outputs, builds latency table (Windows-safe)
  |-- generate_problems.py  Generates Timeloop problem YAMLs for new layers
  |-- layer_defs.py         All network layer definitions
  |-- problems/             Auto-generated problem YAML files (28 new layers)
  |-- outputs/              Timeloop stats for new layers (filled by run_latency.sh)
  |-- latency_report.txt    Final report (generated by compute_latency.py)

HOW TO RUN (WSL)
----------------
Step 1: Open WSL and activate the Timeloop environment

Step 2: Navigate to the latency folder
    cd "/mnt/d/uni work/Semester 8/BACHELOR/Codes/udp_nn/latency"

Step 3: Make the script executable (only needed once)
    chmod +x run_latency.sh

Step 4: Run all networks
    ./run_latency.sh all

    OR run individual networks:
    ./run_latency.sh ic      # ResNet-8 only
    ./run_latency.sh kws     # DS-CNN only
    ./run_latency.sh vww     # MobileNetV1 only
    ./run_latency.sh ad      # AutoEncoder only

EXPECTED RUNTIME
----------------
  84 Timeloop mapper jobs total (new layers x 3 archs)
    - IC:  6 layers x 3 = 18 runs
    - KWS: 1 layer  x 3 =  3 runs
    - VWW: 17 layers x 3 = 51 runs
    - AD:  4 layers x 3 = 12 runs

  Estimated runtime: 1.5 - 3 hours
  (Script skips already-computed runs, so it is safe to re-run)

READING RESULTS
---------------
After ./run_latency.sh completes, open:
    latency_report.txt

Or run just the report step (no Timeloop) from Windows PowerShell:
    python compute_latency.py ^
        --tl-outputs ..\timeloop\outputs ^
        --lat-outputs .\outputs ^
        --out .\latency_report.txt

NOTES ON KWS
------------
KWS conv1 (10x4 kernel) is incompatible with opt_a/opt_b arrays.
For KWS opt_a/opt_b total latency, conv1 uses the base-array cycle
count as a conservative estimate. This is noted in the report.

NOTES ON MISSING LAYERS
------------------------
If a layer shows "MISSING" in the report, it means Timeloop did not
find a valid mapping (e.g., array too small for the spatial dimensions).
In that case, the network total for that arch shows N/A.
This is a valid thesis finding: some optimised arrays cannot serve
all network shapes.
